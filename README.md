# Sijil

<div dir="rtl" align="right">

## سِجِل

**نسختك على السجل.**

</div>

**Your clipboard, on the record.**

A clipboard manager for macOS. Native Swift, no server, no subscription, and no
analytics.

Everything you copy is recorded, deduplicated by content, searchable
substring-wise, and written to a folder of Markdown notes you control. Point that
folder at iCloud Drive, Dropbox, Google Drive, or an Obsidian vault and whatever
sync client you already run keeps it in step — there is no sync API, no OAuth,
and no rate limit to design around.

## Why the folder design works

Clipboard items are **immutable once written**. Two machines writing the same
clip produce byte-identical files; two machines writing different clips produce
different files. There is no merge case, so a synced folder is a complete sync
backend rather than a compromise.

Day-bucketed paths (`Clips/2026/10/18/`) keep per-directory entry counts low,
which matters for iCloud's metadata handling.

## Build

```sh
make test    # 296 unit tests across two targets
make app     # builds dist/Sijil.app
make run     # builds and launches
make install # copies to ~/Applications
```

Requires Xcode 16+ (developed against Xcode 26, Swift 6). SwiftPM builds the
logic; a script assembles the `.app` bundle. The bundle matters — TCC keys
permissions to a bundle ID plus code signature, so a bare executable cannot hold
a stable Accessibility grant.

## First run

1. Launch from the menu bar (no Dock icon).
2. Press **⇧⌘V** to open the history panel. Hold the shortcut, arrow through
   items, and release to paste the highlighted one.
3. Grant Accessibility when prompted, or sijil falls back to copy-only.

### Vault location

Settings ▸ Vault ▸ Choose Folder. The default lives in Application Support,
which needs no permission. Point it at:

| Target | Path |
|---|---|
| iCloud Drive | `~/Library/Mobile Documents/com~apple~CloudDocs/Sijil` |
| Dropbox | `~/Library/CloudStorage/Dropbox/Sijil` |
| Google Drive | `/Volumes/GoogleDrive/Sijil` |
| Obsidian vault | any vault folder — it is just a folder of Markdown |

## Note format

```markdown
---
id: 0199f2c1-4b2a-7c3d-9e1f-5a6b7c8d9e0f
ts: 2026-10-18T14:32:10Z
kind: text
sha256: 9f2b...
source_app: "Safari"
pasteboard_types: ["public.utf8-plain-text"]
char_count: 1284
schema: 1
---
the payload, verbatim
```

Binary payloads (images, PDFs) live in `assets/`, content-addressed, and are
embedded with `![[name.png]]`. Metadata is only ever in frontmatter, so the note
body stays paste-clean.

The sidebar filters by All / Pinned / Locked / Collection; collections can be
created, renamed, and deleted from it.

## Privacy

Clips marked `org.nspasteboard.ConcealedType`, `TransientType`, or
`AutoGeneratedType` by the source app are **never recorded**, and no settings
toggle can override that. Password managers set these.

Source-app detection is a heuristic — there is no public API for "which app wrote
the pasteboard" — so it is treated as advisory metadata and never used for
access decisions.

Retention prunes by age and item count, always exempting pinned, locked, and filed
items. Retention is a *local* decision and never emits a tombstone: expiry on one
machine must not delete anything on another.

### Secrets

Beyond the privacy markers, copies are inspected before they can reach disk:

- Copies from a known password-manager bundle id are dropped outright,
  independent of content, because their output is a credential essentially
  without exception.
- Text is checked for private keys, JWTs, provider API keys, bearer tokens,
  credential-bearing URLs, database connection strings, Luhn-valid card numbers,
  and high-entropy assignments to secret-like names.

The trade-off is deliberately **precision over recall**. A false positive silently
removes something the user meant to keep, from a background service they are not
looking at, with no way to recover it. A false negative costs one extra stored
secret. Every rule therefore requires corroborating evidence — a keyword *and* a
shape, or a checksum that cannot occur by chance — and `.env` placeholders like
`password=changeme` are explicitly not secrets.

Detection can be turned off in Settings ▸ Privacy.

## Durability

SQLite is authoritative for local state; the vault is a replica that any machine
can rebuild from.

- **Atomic publication.** A note is written to a dot-prefixed temp file in the
  destination directory, flushed with `F_FULLFSYNC`, renamed into place, and the
  directory itself flushed. `Data.write(options: .atomic)` renames but never
  flushes, so a crash could lose a note the app already considered written.
- **Write obligations.** Committing a clip also arms its export in the same
  transaction, so a clip can never exist with no pending vault write. A note that
  goes missing from disk re-arms rather than implying deletion.
- **Sound tombstone collection.** Tombstones are not pruned on age. An age-based
  TTL resurrects deleted data on any replica that was offline longer than it, so
  each device publishes an acknowledgement watermark and a tombstone is collected
  only once every known replica has seen it.
- **`secure_delete = ON`**, so a deleted clip's text does not survive in freed
  pages, plus periodic `VACUUM` and FTS5 `optimize`.

## Architecture

```
SijilCore/   PasteboardMonitor, extraction, SQLite + FTS5, Markdown vault,
              transform catalogue, previews, collections
SijilPaste/  CGEvent synthetic paste, Carbon global hotkey, panel key monitor
SijilApp/    NSPanel shell, SwiftUI views, settings
```

SQLite and the vault are **dual-written, not master/slave**. SQLite takes every
capture immediately; the vault flushes on a 30-second debounce. Either can be
rebuilt from the other, so neither is a single point of loss. Import is strictly
read-only — a bug there cannot destroy notes.

## Notes on the tricky parts

**Clipboard polling.** There is no push API; every manager polls `changeCount`.
0.4s is tuned to avoid *missing* copies (copy → switch → paste → switch → copy
can happen inside a second), not to save CPU. `Timer.tolerance` is what actually
saves battery.

**Multi-item pasteboards.** Copying ten files in Finder produces ten
`NSPasteboardItem`s, and some apps emit two per copy. All merge into one history
row.

**Synthetic paste.** `CGEvent` with a combined-session-state source, the
`0x000008` physically-down flag bit, local-event suppression, and per-layout
keycode resolution. `AXUIElement` menu-walking is more semantically correct but
breaks on localisation, apps with no AX tree, and any open menu — and is
incompatible with App Sandbox.

**Global hotkeys.** Carbon's `RegisterEventHotKey` is the only public API that
needs no TCC prompt, and it fires while our own panel is key, which is what makes
Quick Mode possible.

**macOS 27.** `NSPasteboard.accessBehavior` (macOS 15.4) is handled from launch.
It is inert through 26 and enforced by default on 27.

**Title sanitisation.** Titles pass through a guard against pathological
scalars; on macOS 26 these can wedge CoreText and lock the app at 100% CPU
permanently, because the offending title is persisted.
